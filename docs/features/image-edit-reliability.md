# 图生图与图改图故障修复

用户报告连续修改时出现 `Failed to fetch`，授权重点审查并沿既有测试、上线范围修复。

## 已核实与范围

- 自有作品读取依赖构建时的占位 OSS origin，生产域名不同便跨域 fetch；生产原图响应无允许跨域读取头。
- 自有作品改用 jobId/index 定位的同源鉴权原图接口，兼容旧引用；鉴权失败不得绕回公开 OSS。
- GIF 作品编辑取首帧为静态参考，重新生成动图，保留原动画参数。明确静态请求才退出动画；不承诺原 GIF 逐帧编辑或运动一定符合提示。
- 上传 PNG/JPEG/WebP 保持现有支持；不增加外部 GIF 上传和任意 URL 代理。
- 参考图读取失败明确说明尚未创建任务；未知接单一律先按原 requestKey 查询，不依赖再次读取旧参考图。
- 上游接单结果不明时停止自动再次生成；不能静默移除蒙版重发。
- 不改变网站按张计费、视频权限、数据库结构或现有任务所有权验证。

## 验收与回退

覆盖不同 OSS 域名且无 CORS、至少连续两次静态编辑、GIF 首帧转换与动画参数继承、上传编辑、原图越权/过期、未 POST 的错误提示、响应丢失后旧参考图不可读仍可按原 key 恢复，以及供应商接单后断流不重复调用、蒙版不被移除。

执行适用类型/lint/单测/构建、浏览器、隔离 PG 与真实授权供应商检查。保留失败原始证据，最终测试绑定被部署产物。发布前保留原 release 和生产 PG 备份，独立核验恢复；不恢复旧快照覆盖新写入。

发布后观察至少 120 秒、6 轮：健康、生图公开、视频内部限制、静态文件哈希、运行二进制一致、无意外重启及新增 ERROR/非预期 5xx。关键检查失败停止发布并回切应用，继续使用当前数据库。

实施与验证状态见 STATUS；当前轮未完成的检查不记为通过。

## 本轮上下文与等待反馈增量

- 本轮上传优先于历史作品，显式不使用参考除外；模型的 useReference=false 不覆盖用户指定参考。
- 纯文本修改在当前创作范围内自动读取最近已交付作品；没有作品时可继续当前已指定参考，不跨独立新图/新上传边界。
- 明确新图截断旧对话和旧图、旧 GIF 参数；边界随用户消息持久化，界面历史保留。
- 未出方案卡的流式等待持续显示理解/整理状态；方案到达、结束、停止或失败立即结束，不显示虚假百分比，并支持减少动态效果。
- 不新增依赖、模型调用、收费、权限或数据库结构。按上一节发布回退与观察阈值，覆盖三类上下文、刷新、参考字节、模型错误关闭参考、GIF与等待中断。

- 用户追加模型顺序：静态生图与图改图按 2.6 Flare、2.5 Flare、2.5 Sunburst、2.6 Sunburst、Image 2 调用。用户提供测速排序，本轮不把其报告当作本轮实测数据；GIF 专用模型保持既有兼容边界。
- 首轮 CI 发现“再来一只橘猫”被误识别为续改，保留原断言，修复为独立创作后重跑相关与全量检查。
