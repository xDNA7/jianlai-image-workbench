## 内部访问方案和待确认

现有普通 bootstrap 自动创建账户，不能识别内部人；现有管理员 Cookie 的 Path
不覆盖普通API，不能直接作为视频认证。建议视频独立内部登录（共享口令，非管理员权限），
服务端哈希、HttpOnly/Secure cookie、同源/CSRF检查、失败限流、8小时过期和退出；进程重启后需重新登录。
口令已通过安全输入渠道提供，服务端仅保存scrypt哈希和盐，不写源码或聊天，不向内部用户授予管理权限。
该方式已随样板获用户确认，正在实现。若需要逐人撤销而非共享口令，另定范围。

应保护视频分镜聊天（含mode绕过）、创建/按key查询/列表/详情/媒体签名与混排视频数据；
生图API和图片画廊继续公开，未验证内部身份时不得暴露视频数据。API Key继续仅服务端持有。
不扩大管理员Cookie路径，不把随机URL当认证。退出/过期时清理视频状态、预览和迟到响应。
现有OSS已签发链接的有效期与直接访问边界须在上线前核实，不宣称能撤销已下载媒体。

### 实现阶段核对

- 用户2026-11-09明确回复“可以”，原型/UI与独立口令范围已批准。
- 内部会话：8小时、账户绑定、内存opaque token；重启需重新登录；登录按可信代理真实IP
  +普通账户限流，并限制全局scrypt并发；独立cookie不是管理员cookie。
- 生效代理只在剑来API location补覆盖 `X-Real-IP $remote_addr`，后端仅loopback信任该header。

  应用媒体代理GET/HEAD/Range保持账户归属；签名只在服务端使用。
- 仓库新增AGPL全文、NOTICE、改编模块来源；视频工作区提供对应源码入口。
